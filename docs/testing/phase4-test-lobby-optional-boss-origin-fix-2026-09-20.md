# Phase 4 TEST Temple optional side rooms: Base-origin eligibility fix — 20 September 2026

## User-observed issue

The TEST Roblox player completed Temple Room 1, walked past a side room, completed Room 2, and returned to that side room; neither of the two visible side arenas activated. Ordinary encounters worked. Cloud occurrence is a reported gameplay symptom; **no F9 server session plan from that exact run has yet been obtained**. Do not conflate the two optional arenas: the current Depth1 code calls the arena after Room 1 an **EventArena** and the arena before the boss a **SecretArena**.

## Source defect and contained fix

`TeleportCoordinator:start_dungeon` creates and persists `DungeonInstanceDirector.resolve(..., DungeonInstanceDirector.runtime_options(), ...)` **while the player is still in Base/Lobby, before teleport**. The pre-fix `DungeonInstanceDirector.runtime_options()` granted the 30-minute TEST Event window and 100% TEST secret-route chance only when `DungeonTestPlaceholderRelease.is_test_dungeon()` was true. That returns false on the exact allowlisted TEST Lobby place `134132328219009`. Therefore a new normal teleported TEST run could be frozen with no optional Event/Secret eligibility, despite the Dungeon place containing both visible placeholder side rooms and the Dungeon code knowing the exact TEST dungeon place `117293035754309`.

Changed only `src/ServerScriptService/Core/Services/DungeonInstanceDirector.luau` to use the existing `DungeonTestPlaceholderRelease.is_test_temple_context()` predicate (exact TEST universe `10765241947` and exact TEST Lobby or TEST Dungeon place IDs). The frozen window/secret chance are now issued at **Base-side entry**, and direct Studio TEST Dungeon simulation retains the same behaviour. Unrelated places, PROD, unreleased Mine and player DataStores are unaffected. This does **not** grant a new optional encounter to a previously created/persisted run.

The authored existing-cloud-place-only script `scripts/studio/patch_test_cloud_lobby_optional_origin.commandbar.luau` is a guarded EDIT-mode, one-ModuleScript hotfix. It requires exact TEST Lobby place/universe, confirms the release helper and old source signature, changes only the one local `DungeonInstanceDirector` ModuleScript's Source, and reports already-applied/no-change on a second run. It refuses unexpected older/newer module versions rather than overwriting source. It **does not** publish, edit the dungeon place, clear old sessions, delete profiles, or change Workspace/portals/geometry. Before running, make a verified dated `File > Save to File` backup of the **CURRENT CLOUD TEST LOBBY** and keep its current Creator Version History reference. Publish only that same authenticated cloud Lobby after applying and reviewing the one-module change, then rejoin a new cloud server and create a **new** dungeon run.

## Separate encounter-ordering / backtracking behavior

The current Depth1 plan contains **one EventArena inserted after the first combat encounter, and one SecretArena inserted before the final boss**. The Event descriptor has `CompletionRequired=true` once active; it currently blocks progressing to Room 2 until cleared. The Secret descriptor has `CompletionRequired=false` but `DungeonEncounterFlow:skip_secret_before` permanently sets it to Skipped when the player enters its direct successor; a skipped secret cannot later be started. These rules predate and are not changed by this eligibility bug fix. The user's wish to pass an optional arena and return later is a **separate gameplay-design/flow task** and is **not proven repaired** by this contained fix. In a new correctly eligible run, the Event arena should be entered after Room 1, and the Secret arena should be entered after Room 2 before entering the final boss; testing actual physical trigger walk-in/feedback and confirming the intended backtracking rule remain necessary.
